# 多用户身份与数据隔离

核对日期：2026-11-24。以下为当前实现，不是早期阶段计划。正式站已上线。邀请码和数据库连接不得写入本文。

## 1. 身份与注册

- Better Auth 1.7.27，邮箱加密码，scrypt 哈希，会话在认证库，Cookie HttpOnly、生产环境 Secure、SameSite=Lax，7 天。
- 前端 `/register` 与 `/login`。Production 仅在 `AUTH_SIGNUP_ENABLED=1` 且邀请码校验通过时允许注册。邀请码走请求头，服务端比对；前端隐藏按钮不算保护。
- Preview 可只开注册开关、不强制邀请码。Production 没有邀请码则启动拒绝开放注册。
- 没有邮件发送器。注册不得把 `emailVerified` 标成 true，文档不得声称已发验证信。
- 登录限流约 15 分钟 5 次；注册限流约 15 分钟 8 次。无效 Origin 拒绝写入。
- 私有测试账号脚本仍可把演练用户标成已验证，不开放成公网路由。

## 2. Learner 绑定

- 认证库与业务库分开，没有跨库外键。业务行的 `userId` 是 `Learner.id`。`Learner.authUserId` 对应 Better Auth 用户。
- 公开注册成功后创建自己的 Learner 和默认 `UserSettings`。客户端不能指定 `learnerId`。
- 禁止把新账号绑到 `unbound:original-lab`。本地 SQLite 里该标记只保留测试历史。
- 初始化失败时账号可以存在但无 Learner；登录后 `POST /api/learner/provision` 用会话用户补建，忽略请求体里的伪造 ID。
- 查询身份只来自会话。跨用户资源返回 404，未登录 401。

## 3. 数据库隔离

- 本地单用户：SQLite `data/lab.db`，供本机 `8787` 和测试。**不迁到 Production 账号。**
- Preview：Neon development 端点，schema `lab_phase_h` / `lab_phase_h_auth`。
- Production：另一 Neon 端点，同一数据库名 `neondb`，同样两个隔离 schema。启动检查拒绝 development 端点、拒绝 `public`。
- 业务约束仍按用户划分课程、词汇、FSRS、复习事件、学习记录和 AI 次数。`clientRequestId` 在用户范围内唯一。
- StudySession 在隔离 schema 有跨用户触发器；Production 启动要求该约束已存在，启动过程不自动迁移。

## 4. AI 额度

- 默认 `AI_USER_DAILY_LIMIT=200`，`AI_SITE_DAILY_LIMIT=1500`，学习日 `Asia/Shanghai`。
- 只对实际发给 DeepSeek 的请求预留并计次。查看音标、浏览器朗读、缓存命中、离线课、FSRS、统计不扣次。
- 金额预算可选。未配置预算不因此拒绝已授权请求。
- Production 已验证一次真实探测会扣 1 次。整课生成仍走离线路径，未验证为模型课程。

## 5. 安全边界

- 不把邀请码、`.env*`、`.invite.production`、连接串写入文档或 Git。
- 不关闭 Vercel Standard Protection，除非当轮明确要求。
- 不把 DeepSeek 密钥放到 Preview 启动路径；Preview 启动拒绝携带可直接调用的模型密钥。
- CORS 与受信 Origin 必须是明确 https 域名。
