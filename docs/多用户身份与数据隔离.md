# 多用户身份与数据隔离

核对日期：2026-11-23。阶段 A 已在代码中实现；用户归属及之后的阶段仍是**计划中**。

当前事实：`main` 为 `52f09c9`。FSRS 正式复习已是单库事务，`clientRequestId` 仍是全局唯一。本地库是 SQLite，Prisma 6.19.3。学习日仍用服务器本地时区的 `localISODate`。全部学习接口没有登录检查。

## 1. 身份验证

选用 **Better Auth 1.7.27**。阶段 A 已在独立 SQLite 认证库接入登录、会话和数据库限流。公开注册关闭。业务表还没有 `userId`，学习接口仍未按身份保护。

阶段 A 已锁定 Better Auth 1.7.27，许可证为 MIT。Prisma 仍是 6.19.3。认证 Prisma Client 单独生成，不覆盖业务客户端。

第一版只开邮箱加密码：

- 密码由 Better Auth 使用 Node.js 自带的 **scrypt** 哈希，存在 `account.password`。不另写哈希。
- 会话存在数据库 `session` 表。Cookie 为 HttpOnly；生产环境 `Secure`；`SameSite=Lax`。有效期 7 天。退出删除服务端会话。
- 公开注册关闭：`emailAndPassword.disableSignUp: true`。`POST /api/auth/sign-up/email` 对公网返回拒绝。
- 私有测试账号由本机脚本通过 Better Auth 的服务端 API 创建，并直接标记 `emailVerified: true`。脚本不开放成路由。
- 公开注册、邮箱验证信和自助密码重置，要等邮件发送器与安全验收都完成后再开。第一版不接邮件服务，也不把重置链接写进日志。
- 忘记密码在第一版由同一个本机脚本重置。重置后撤销该用户全部会话。

防暴力尝试使用 Better Auth 的限流，并改成数据库存储：

- `rateLimit.enabled: true`
- `rateLimit.storage: "database"`
- 登录路径收紧到同一 IP 每 15 分钟 5 次。默认的 10 秒 3 次不够。
- 开发环境也要能用测试打开限流。内存限流不能用于 Vercel 的多个实例。

第一版不增加 Redis 或其他持久化限流服务。认证限流表和后面的 AI 次数都放在现有 SQLite / PostgreSQL。只有数据库限流被实测证明不够时，才另议外部存储。

前端使用 `better-auth/vue`，请求带 Cookie。Vite 继续把 `/api` 代理到 `127.0.0.1:8787`。生产 CORS 只允许明确的站点来源，并打开 `credentials`。

## 2. 数据归属

Better Auth 拥有 `user`、`session`、`account`、`verification`。业务表增加 `userId`，外键指向 `user.id`，删除用户时级联删除其学习数据。会话表不级联进学习记录。

所有查询的用户 ID 只来自服务端会话，不接受请求体里的 `userId`。资源不属于当前用户时返回 **404**，避免用 403 暴露资源存在。未登录返回 **401**。

| 模型 | 归属 | 约束与索引 |
| --- | --- | --- |
| UserSettings | 每用户一行 | 去掉 `id = 1`。`userId` 唯一外键。保留现有设置字段。 |
| DailyLesson | 课程属于用户 | 唯一约束从 `(lessonDate, version)` 改为 `(userId, lessonDate, version)`。索引 `(userId, lessonDate, active)`。 |
| Vocabulary | 单词属于用户 | `userId` 必填。有课程时必须与课程的 `userId` 相同。`lemma` 不设全局唯一。索引 `(userId, lemma)`。 |
| WordProgress | 跟随单词，并冗余 `userId` | 保留 `vocabularyId` 唯一。新增 `userId` 外键和 `(userId, due)` 索引。写入时 `userId` 必须等于单词的 `userId`。 |
| ReviewEvent | 事件属于用户 | 新增 `userId` 外键。`vocabularyId` 仍然不加外键。去掉 `clientRequestId` 全局唯一，改为 `(userId, clientRequestId)` 唯一。索引 `(userId, vocabularyId, createdAt)`。 |
| QuizQuestion | 通过课程归属 | 不单独加 `userId`。读取和作答必须连到当前用户的课程。 |
| QuizAttempt | 作答属于用户 | `userId` 必填，且必须等于题目所属课程的用户。 |
| StudySession | 学习记录属于用户 | `userId` 必填。带 `lessonId` 时课程必须属于同一用户。 |
| AIUsageRecord | 每次付费调用属于用户 | `userId` 必填。索引 `(userId, createdAt)` 和 `(createdAt)`。 |
| ExplanationCache | 见下一节 | 不挂课程外键。 |

`clientRequestId` 的查找条件是当前 `userId` 加请求号。另一个用户使用相同请求号不是重放，也不读到前者的复习结果。同一用户、同一请求号、不同单词或评分，仍返回 `REQUEST_REUSED`。多个空请求号继续允许。`mirrorLemma` 只能镜像同一用户的同形词，不能跨用户复制 FSRS。

已有学习记录全部归到迁移时创建的一个初始账号。新注册用户从空数据开始，不复制初始账号的课程、进度和复习事件。

## 3. AI 缓存

当前正式解释仍读 `data/preview-explanations.json`。SQLite schema 没有 `ExplanationCache`。文件键是 schema、篇章和单词，读出后再比对完整句子。Neon schema 里有独立的 `ExplanationCache`，本轮没有核对它的键是否包含完整句子。

多用户规则：

- 可共享的缓存键必须包含 schema 版本、篇章、单词和**完整句子**。只按单词命中是错误的。
- 相同的课程原句可以复用，不按用户复制一份。
- 用户私有文本使用另一个键，键内包含用户 ID，并且只有该用户能读。
- 私有文本不得写入共享键。缓存行不挂课程外键。
- 本地 JSON 文件不能作为多用户缓存。Vercel 上使用数据库。

## 4. 旧数据迁移

只在数据库副本上设计和演练。本轮没有备份、没有写入 `data/lab.db`，也没有连接 Neon。

迁移前重新做只读计数。2026-11-23 的只读基线是 5 节课、30 个单词、30 条进度、11 条复习事件，请求号都为空。这不是永久数量。FSRS 的 due、stability、difficulty、state、reps、lapses、lastReview 原样复制，不调用调度器。`lessonDate` 字符串原样保留。时间戳继续按 SQLite 的 Unix 毫秒解释。

步骤：

1. 停止本项目 API，避免 WAL 还在写入。
2. 用 SQLite backup API 备份 `data/lab.db` 到 `D:\Backups\English-Listening-Lab`。备份必须能只读打开，并与源库计数一致。不把备份提交到 Git。
3. 复制备份为演练库。后续全部写在演练库。
4. 用 Better Auth 在演练库创建初始账号，密码由 scrypt 生成。
5. 在同一个事务里：增加可空 `userId`，把现有业务行更新为初始账号，核对行数和原有关联，再改为非空并替换唯一索引。
6. 核对课程、单词、进度、复习事件、题目、作答、学习记录和设置都指向该账号；复习事件仍是 11 条且时间戳未变；进度合计未变。
7. 演练库验收后才允许在后续授权窗口替换本地运行库。替换前再次备份。

SQLite 不能直接修改已有唯一约束，涉及 `DailyLesson` 和 `ReviewEvent` 的部分使用建新表、复制、改名。脚本使用显式 `BEGIN` / `COMMIT`，计数不符就 `ROLLBACK`。

PostgreSQL 使用 `prisma-neon` 的新版本化迁移，文件内写显式 `BEGIN` / `COMMIT`。Prisma 6.19.3 不保证整份迁移默认有事务。密码哈希不写进迁移文件。账号创建和回填放在受 guard 保护的演练脚本里，并与约束切换处于同一事务。`20261123143000_review_request_id` 的失败回滚仍未在隔离 PostgreSQL 执行，不能标成通过。

失败回滚：

- 事务未提交：数据库保持原样。
- SQLite 已替换运行库：停 API，用验证过的备份文件恢复，并删除残留的 WAL/SHM，再只读核对计数。
- PostgreSQL 已提交但验收失败：恢复迁移前的 development 备份或分支。不连接 production，也不把 production 指到开发库。这个恢复步骤还没有执行过。

## 5. API 权限

`/api/health` 保持公开，只返回 `{"ok":true}`。`/api/auth/*` 由 Better Auth 处理，登录和重置受数据库限流。其余接口都要会话，并且只能访问自己的行。

| 接口 | 权限 | 额外限制 |
| --- | --- | --- |
| `GET /api/health` | 公开 | 不返回环境或连接信息 |
| `GET /api/system` | 登录 | 不返回密钥 |
| `POST /api/ai/test` | 登录 | 确认费用后计入用户和全站额度 |
| `GET /api/dashboard` | 登录 | 只统计当前用户 |
| `GET/PUT /api/settings` | 登录 | 只读写当前用户的 `UserSettings` |
| `POST /api/lessons/today` | 登录 | 学习日按 `Asia/Shanghai`；唯一约束含用户 |
| `POST /api/lessons/ai-version` | 登录 | 付费额度；只基于当前用户的课程 |
| `POST /api/lessons/:id/activate` | 登录且拥有该课 | 只切换该用户同一学习日的版本 |
| `GET /api/lessons/today/versions` | 登录 | 当前用户、当天 |
| `GET /api/lessons`、`GET /api/lessons/:id` | 登录 | 列表和详情都过滤 `userId` |
| `PATCH /api/lessons/:id/progress` | 登录且拥有该课 | |
| `POST /api/lessons/:id/recall` | 登录且拥有该课 | |
| `POST /api/vocabulary/:id/known` | 登录且拥有该词 | 正式 FSRS；请求号限定当前用户 |
| `POST /api/vocabulary/:id/easier` | 登录且拥有该词 | 付费额度 |
| `GET /api/review` | 登录 | 只排当前用户到期词 |
| `POST /api/review/:id/practice` | 登录且拥有该词 | 不改变排程 |
| `POST /api/review/:id/rate` | 登录且拥有该词 | 正式 FSRS；快照和请求号都在用户范围内 |
| `GET /api/library` | 登录 | 当前用户的词 |
| `GET /api/stats` | 登录 | 当前用户的真实记录 |
| `POST /api/quiz/:id/answer` | 登录且拥有题目 | |
| `POST /api/quiz/:id/simpler` | 登录且拥有题目 | 在线生成时计入额度 |
| `POST /api/sessions` | 登录 | `lessonId` 必须属于当前用户 |
| `POST /api/tts` | 登录 | 浏览器语音不收费；在线 TTS 计入额度 |
| `GET /api/audio/:name` | 登录 | 文件名校验保留；不向未登录用户提供 |
| `GET/POST /api/preview/explain` | 登录 | 共享键不含私有文本；付费生成计入额度 |

额度的建议起点是每用户每个上海日 20 次付费调用、全站每个上海日 100 次。这只是设计值，实施前需要确认。先写 `AIUsageRecord` 再调用模型；超限返回明确错误，不发送请求。CORS 和隐藏按钮不能代替这些检查。

## 6. 学习时区

新的学习日用 `Asia/Shanghai` 计算，配置名 `STUDY_TIMEZONE`。不用服务器本地时区，也不使用 `Date#getFullYear()` 的宿主时区。

绝对时间仍是 UTC 瞬间，SQLite 继续存 Unix 毫秒。`lessonDate` 是 `YYYY-MM-DD` 日历字符串。历史值不换算、不改写。FSRS 的 `due` 继续是绝对时间。

上海无夏令时，跨日边界是 UTC 当天 16:00。测试至少包括：

- `2026-11-22T15:59:59.999Z` 是上海的 `2026-11-22`。
- `2026-11-22T16:00:00.000Z` 是上海的 `2026-11-23`。
- 进程时区设为 UTC 时，上面两个结果不变。
- 6 月和 12 月的上海偏移都是 `+08:00`。
- 一条已存在的 `lessonDate` 在迁移和跨日后字节不变。
- 23:50 开始、00:10 结束的学习记录保留各自的绝对时间，新课程使用新的学习日，不回写旧课日期。
