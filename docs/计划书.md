# 计划书

核对日期：2026-11-23。阶段 C 的隔离运行时已经验证。`data/lab.db` 仍是 8787 的单用户库，还没有绑定真实账号。

`docs/多用户身份与数据隔离.md` 里的阶段字母和这里不同。那份文档的阶段 C 是旧数据迁移；对应演练已在阶段 B 的副本完成。当前阶段 C 是多用户运行时接入，不是替换运行库。

## 已验证

- 三套 Prisma 6.19.3 客户端分开生成：单用户 `@prisma/client`、认证 `src/generated/auth`、多用户 `src/generated/user`。
- 多用户运行时只接受 `data/user-runtime*.db` 和 `data/auth-runtime*.db`。缺少配置不会连接 `lab.db` 或 `auth.db`。
- 隔离测试覆盖数据库、内部服务和 HTTP。用户 A/B 互不可读，伪造 `userId` 无效，未登录为 401，未绑定为 403，异常绑定为 409，跨用户资源为 404。
- 同一个 `clientRequestId` 可以分属两个用户。演练事务回滚不改原始 FSRS 和 `lessonDate`。`unbound:original-lab` 没有被自动绑定。
- `npm test` 通过：`selftest ok`、`auth selftest ok`、`user drill ok`、`user runtime ok`。
- 测试前后 `lab.db` 与 `auth.db` 的文件状态和只读计数一致。8787 的 `/api/health` 仍是 `{"ok":true}`，没有多用户测试路由。

## 已实现

- 身份解析、显式绑定和按 Learner 限定的课程、词汇、进度、复习、学习记录、AI 用量、答题访问。
- 独立入口 `npm run user-runtime -w @lab/server`。必须设置 `USER_RUNTIME=1`，只监听 `127.0.0.1`，默认端口 8797，拒绝占用 8787。
- 现有 `createApp` 和 `npm run dev` 仍走单用户库。多用户路由没有挂到现有业务接口。
